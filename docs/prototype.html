repairs Repair jobs, status, appointments
Column Type Nullable Description
tenant_id string No Your organisation ID (nhg-001). Same on every row — confirms data isolation
repair_id string No Primary key. Stable identifier for the repair job
property_id string No Foreign key to properties.property_id
status string No Current status. Values: OPEN, IN_PROGRESS, COMPLETED, CANCELLED
priority integer No Priority level 1-5 (1 = emergency, 5 = planned)
category string No Repair category (e.g., PLUMBING, ELECTRICAL, HEATING)
description string Yes Short description of the repair (PII redacted)
reported_at timestamp No When the repair was first reported (UTC)
completed_at timestamp Yes When the repair was completed (UTC). Null if not complete
created_at timestamp No Record creation time in source system (UTC)
updated_at timestamp No Last business-data update (UTC)
exported_at timestamp No When this record was exported (UTC)
is_deleted boolean No Tombstone flag. True if record was deleted in source

Tenant isolation

How we ensure you only receive your organisation's data

✓
Your data is isolated — Every export job runs with your tenant ID (nhg-001) enforced at the database level. Cross-tenant data access is technically impossible.
How tenant isolation works
-- Your export query (simplified)
SELECT * FROM repairs
WHERE tenant_id = 'nhg-001' -- Enforced by Row-Level Security
✓ This filter is applied automatically at the database level
✓ Cannot be bypassed by application code
✓ Verified by automated tests on every deployment
Security controlHow it protects you
Row-Level Security (RLS) Database enforces tenant filter on every query. Even if application code has a bug, wrong data cannot be returned
Separate export jobs Your export runs as a dedicated job with your tenant credentials. Never shared with other organisations
Isolated storage Files are written directly to YOUR bucket using YOUR credentials. No shared staging area
Automated isolation tests Every deployment runs tests that attempt cross-tenant access and verify it fails
External penetration testing Independent security firm tests for tenant isolation bypasses quarterly
Audit logging Every export is logged: what data, when, where it was sent. Available on request

API reference

Programmatic access to your data export configuration and status

Authentication

All API requests require an API key in the header:

Authorization: Bearer your-api-key-here

Generate API key in your account settings.

Endpoints
Method Endpoint Description
GET /v1/exports/latest Get status of the most recent export
GET /v1/exports/history List all exports with pagination
POST /v1/exports/trigger Trigger a manual export
GET /v1/config Get current export configuration
PUT /v1/config/destination Update destination configuration
GET /v1/schema/{dataset} Get schema for a specific dataset
Example: Get latest export 
curl -H "Authorization: Bearer $API_KEY" \
  https://data.plentific.com/v1/exports/latest
